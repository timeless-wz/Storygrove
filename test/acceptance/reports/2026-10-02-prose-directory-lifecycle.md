# 正文目录、候选稿、回收站与全书连续编号：分项验收

日期：2026-10-02。实施基线：main / 523ed8c。范围：用户确认的卷章菜单、重命名、撤销删除、同章多稿与正文连续编号。

## 任务 1：目录操作与重命名 — 通过

- 卷行右侧原删除按钮改为添加章节「＋」，移除卷下面重复的添加章节行；目录顶部保留添加卷，并增加回收站入口。
- 卷右键菜单提供添加章节、重命名卷、删除卷。删除卷时章节移入未归卷，卷进入回收站。
- 章节右键菜单提供前／后插入新章、添加同章候选稿、移动／排序、重命名、移入回收站；各稿件旁的菜单按钮也提供重命名与删除，便于键盘操作。卷菜单支持 Shift+F10。
- 新建草稿有章节名称；普通草稿章号可重复，插入新章则自动分配新身份，发布时按正文位置编号。
- 编辑器优先使用稿件名称；刷新时更新打开的标签与稿件状态。替换下来的旧正文仍保留原正式名称。

证据：浏览器目录、编辑器与标题回归；`evidence/prose-directory/context-menu.png`；仓储重命名及旧标题保留测试。

## 任务 2：回收站、恢复与撤销删除 — 通过

- 新增项目持久化回收站；删除仅隐藏该稿件并保存原状态，正文、修稿／审稿记录及原排序位置仍在数据库中。
- 删除后显示撤销删除；回收站可以恢复或永久删除，永久删除在 UI 中二次确认。
- 重开项目仍能恢复；若该章已有新正文，旧正文恢复为草稿，不覆盖新正文。
- 恢复卷会恢复尚未移动到其他卷的章节；删除后的人工归卷不被覆盖。
- 删除前先保存同一稿件的未保存标签，包括缺少 draftId 的旧标签。保存失败即停止删除并保留输入。
- 回收站稿件被排除于普通读取与导出；过期编辑器保存回收站稿件会明确报错，不伪装为保存成功。

证据：真实 SQLite 删除→关闭→重开→恢复；真实 IPC 会话门禁；`prose-directory-unsaved-input.txt`；`evidence/prose-directory/recycle-bin.png`。

## 任务 3：草稿多候选与唯一当前正文 — 通过

- 同一章节允许多个草稿候选，目录显示全部候选，不再只展示最新一稿。
- 添加候选不会改变已有卷归属，包含只有显式蓝图归属的旧项目。
- 发布已有正文的章节时明确提示替换，提交携带用户确认时的当前正文身份；正文变化后必须重新确认。
- SQLite 事务把旧正文转回草稿再发布新稿；数据库唯一索引保证每章最多一份当前正文。
- 旧项目重复定稿在启动时归一为一个当前正文，其他稿件保留为候选；重复发布、重新发布旧候选仍走既有发布记录。
- 回收站或已被替换的稿件不能通过旧发布重试入口重新成为正文。

证据：候选创建→首次发布→未确认拒绝→确认替换→重新发布旧候选；现有发布、修稿来源、定稿导入与保护回归。

## 任务 4：插入、移动与全书连续编号 — 通过

- `drafts.chapter_number` 继续作为固定章节身份，新增 `prose_chapter_order` 保存独立位置；显示章号由卷顺序与位置计算，只对当前正文连续计数。
- 第一卷第1～10章，第二卷接第11章；未归卷排在已归卷之后。草稿候选不会占用额外正文章号。
- 在章前／后插入新章或把后面的章移到前面时，后续正文章号自动顺延；章节身份、正文内容和显式蓝图绑定不随显示编号改写。
- 移动卷归属与插入位置在同一事务内完成；无效目标回滚全部变更。删除正文后重新顺号，恢复后按原位置重新计算编号。
- 正文编辑器上一章／下一章按目录顺序导航。目录排序变化会使旧连续性投影失效，防止直接复用旧缓存。
- 导出和实体稿使用当前显示编号；导出写入前复核正文事实与排序，变化时要求重新确认。

证据：真实数据库跨卷排序与重开；真实受授权导出控制器；位置及内容断言。

## 任务 5：实体稿同步与发布后编辑 — 通过

- 受管理实体稿采用当前编号、名称和稳定稿件身份生成文件名；历史文件移入 `.vela/trash/prose-projections`。
- 同一项目的实体稿同步串行执行，并校验数据库会话、直接子路径与文件所有权。已有非受管理同名文件不被覆盖。
- 已发布正文再次编辑保存时，先暂存旧实体稿，再以当前数据库快照发布，解决文件发布器拒绝不同内容导致的更新失败。
- 目录事务成功后若文件同步失败，返回明确警告；数据库中的正文与目录事实仍保持已提交状态。

证据：真实文件发布→插入顺号→替换正文→再次编辑保存→移入回收站→恢复；文件名称与内容回读。
