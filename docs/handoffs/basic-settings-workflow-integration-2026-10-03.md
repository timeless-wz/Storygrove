## 1. 目标与固定决策

本次要让作者明确三件事：内容在哪里维护；AI 会生成和保存什么；运行进度在哪里看。

1. 基础设定属于内容。继续保留各内容页作为唯一编辑目标。
2. 将现有“AI 生成故事设定”页面改为“基础设定总览”，复用现有 WorldBuildingEditor 和稳定路由，不创建第二个总览。
3. 总览展示内容用途与真实状态；“批量生成设定”是该页的一个次要操作，不再是侧栏里的独立内容分类。
4. 单篇文档原有 AI 按钮保留，明确只预选当前目标；缺少依赖时解释并让用户选择，不默默多选。
5. 右侧“AI 工作流”面板保留，负责执行进度、输出、历史、取消和已有恢复功能。不得删除工作流引擎或把正式文档放进任务历史充当事实来源。
6. 暂不迁移、合并、删除 NovelConfig 或 project_core 字段。不推断哪份旧资料是废案，不自动清空构想，不改变原写作上下文优先级。
7. 把“初始构想”改成准确的“核心构想”，明确它仍会参与生成和写作。语义冲突自动处理、构想停用及正式确认机制不在本次实现中。

不要重新创建五层菜单，也不要在这轮再次搬动情节大纲、世界管理等已整理的入口。侧栏故事设定组仍保留，在组内第一项增加/迁入“基础设定总览”，移除原“AI 生成故事设定”入口。同一原路由只出现一次。情节大纲继续在创作规划，亦可从总览快捷打开；这两个入口必须到同一文档。

## 4. 基础设定总览页面

复用 WorldBuildingEditor。标题“基础设定总览”，描述“维护创作方向、故事前提、人物、世界与全书剧情；可手动编写，也可使用 AI 辅助。”

主区按顺序展示五个内容入口：创作方向、故事前提、角色档案、世界观总纲、情节大纲。角色卡片打开角色档案默认编辑入口，绝不打开角色投影作为可编辑文档。

每个入口只包含：名称、一句话用途、真实状态、主要的“打开编辑”动作。卡片主体可打开，内部辅助按钮不冒泡触发打开。原文档卡片的字数可保留，必须标为字符数；不要以字数证明内容质量。

世界观入口内给出“管理各个世界”的次要链接，打开现有世界管理。同一区域简述“总纲维护共同规则，世界管理维护具体世界及组成”。不把世界管理列作第五个 AI 生成步骤。

页面操作区：

- “批量生成设定”：打开原确认弹窗，不直接调用模型。
- “查看 AI 工作流”：打开已有右侧 ai-output。
- 刷新：保留现有读取与会话保护。

状态规则：

- 文档非空：“有内容”；空：“待填写”。
- 角色：真实角色数量；名单未就绪/待修复必须如实显示，不伪装为空或完成。
- 创作方向：显示“查看与编辑”，并可显示实际有值的题材、篇幅等摘要；不新增猜测完整度。
- 不再在标题显示“3/3 完成”或“5/5 完成”。运行状态单独展示，不与内容状态混合。
- 世界观未完成候选、大纲可恢复状态、当前运行和失败提示保持可见；它们不能因为页面转为总览而被删掉。
- 禁止新增不存在的“已确认/已定稿”状态字段；本次不实现作者确认系统。

桌面可两列，窄窗口一列。使用主题 token 与现有圆角；长标题换行，状态不挤压操作。避免五张巨大横条造成重复留白，也不要用大流程箭头暗示作者必须逐步完成。

## 6. 单项与批量生成语义

冻结一个可测试的入口模式契约，建议使用明确的 discriminated union，名称可按仓库风格调整：

```ts
type ArchitectureLaunchMode =
  | { kind: 'single'; step: ArchStepKey }
  | { kind: 'batch' }
  | { kind: 'resume'; step: 'worldbuilding' | 'synopsis' }
```

- single：只默认选择该 step。若缺少真正必需的来源，显示阻塞原因，提供“去填写”和“加入所需生成步骤”；后者必须由作者明确点击后才选中依赖。
- batch：四个步骤全部展示，初始不勾选，由作者选择；不自动勾选已有内容项或角色重建。空选择不能提交。
- resume：固定对应一步，携带既有检查点参数；不顺带生成其他步骤。
- 废除“缺失集合 + initialSelectedSteps”造成隐式扩大范围的行为；检查全部调用方与既有测试，不能只改函数而漏掉恢复入口。

四个生成步骤显示名为：故事前提、角色资料、世界观总纲、情节大纲；内部 key 不变。

弹窗每项说明输入和输出目标。角色项明确“写入角色档案，图谱由档案投影”；世界观项明确“生成总纲文档，不自动创建世界/势力/秘境记录”。

提交前列出所选项目、已有内容及实际写入方式。不同命令的覆盖/合并/候选方式必须查源码后如实表达，不统一承诺“全部先生成候选”。已有重生成警告与角色保护保留。

依赖检查需要复用/提取现有判定，不能从视觉顺序推断角色一定是世界观的必需依赖。代码当前世界观主要依赖前提与配置；大纲依赖前提、角色投影、世界观。上下文缺失与将由本轮前置步骤补齐应分别处理。

本次不放宽底层校验、不更改保存事务、不新增任意内容长度门槛。文案用“内容缺失或不足”，允许手工补充；不要写成“必须先 AI 生成”。对于只属建议的缺项，保留“警告后继续”，不升级成强制完整四步。

## 7. 工作流面板与单字段 AI

右侧 AI 工作流面板保留现有运行/历史/输出/取消/候选恢复能力。相关位置用简短说明“查看 AI 任务进度与输出”，不把该面板称为正式设定库。

将配置单字段生成接入已有 startWorkflow 引擎，使用一个单步骤 WorkflowDefinition 包装原 GenerateFieldCommand；不要新造执行队列，不复制模型调用或保存代码。

- 捕获字段、项目 lease、配置快照及所需模型语境，沿用现有 generation runtime；不能靠传入字段名后再读另一个项目。
- 与现有整套配置生成共用 novel-config 资源约束；若当前引擎只有整份资源锁，本次使用整份锁，不为此新增细粒度锁系统。
- 一个点击只产生一次命令执行和一次既有保存路径，禁止新旧执行路径并存。
- loading 状态绑定实际运行生命周期，不在 startWorkflow 仅返回 run ID 时提前结束；组件卸载、任务取消和项目切换不能误报告成功。
- 取消前已提交的结果不得声称回滚；沿用引擎和命令的真实取消/提交边界。必须检查原命令是否在模型返回到写入之间校验取消；必要修复限该命令。
- 任务标题应能定位字段，执行失败留在运行记录，成功后从当前项目刷新实际字段；失败不得清空已有输入。
- 不扩大为统一全系统所有 AI 调用。本次只统一此处已发现的单字段入口。

## 10. 验收清单

用临时测试项目和模拟模型执行测试，真实模型测试仅在另有授权且环境允许时进行；不得在用户项目运行重新生成做验收。

1. 总览五类入口均到原内容；角色入口到可编辑档案；世界管理仍是既有实体页面。
2. 旧侧栏 AI 生成入口被总览替代，没有两套总览；旧稳定 tab 可继续使用。
3. 单篇生成仅选本项；其他缺失步骤不被静默勾选。依赖缺失可手工补充或明确加入步骤。

5. 手写有效前提可满足原检查，不要求 AI 来源；原警告型缺项仍允许继续。
6. 单字段生成在工作流面板可见，失败、取消、重复点击、项目切换正确；不双写，已有值不因失败消失。

8. “有内容”不被显示为“已确认”；候选不计作正式文档；角色待修复不是普通空状态。
9. 四个核心构想字段、其他配置、文档、角色与世界关联编辑前后数据不被自动迁移或清空。正文材料 assembly 用例证明本次没有偷偷改取用规则。
