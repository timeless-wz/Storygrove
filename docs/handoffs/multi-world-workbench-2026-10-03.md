## 1. 用户意图与本次目标

一个小说项目有一套总世界观，其下可以有多个具体世界。每个世界必须有自己的介绍，并能围绕该世界维护势力、区域、地点、秘境、规则、人物及历史。作者应该先认识一个完整世界，再进入它的组成部分，而不是面对分散的表单。

本次在既有世界工作台上整理页面和操作路径，不从零建设第二套世界数据库。总世界观长文档与结构化世界资料互补；编辑任何一方不得自动覆盖另一方。

核心验收：选择世界 A 后，能看到 A 的介绍，进入 A 的势力、秘境等分区；切换世界 B 后，看到 B 自己的资料；新建内容明确归属当前世界，跨世界联系明确显示两端。

## 3. 固定概念与关系

```text
项目
├─ 世界观总纲：整个项目的共同背景、规则与世界之间的总体关系
└─ 世界管理
   ├─ 世界 A
   │  ├─ 世界介绍
   │  ├─ 地图与地点
   │  ├─ 势力
   │  ├─ 秘境与特殊空间
   │  ├─ 本地规则
   │  ├─ 相关人物
   │  ├─ 历史事件
   │  └─ 人物行踪
   └─ 世界 B
      └─ 同样的组成结构

跨世界联系：沿用通道和既有实体关联，在相关世界中展示对端
```

- “总世界观”是概念总纲，不创建一个虚假的“总世界”实体来装所有内容。
- 单世界小说同样适用，不强制至少创建两个世界；允许只有名字的未完成世界。
- 世界不是地图。一个世界可无地图或有多张地图；地图原有单世界归属与未归属兼容继续有效。
- 普通秘境属于一个世界，其位置、入口、进入条件、危险、资源和状态沿用原字段。不能因为名字含“小世界”就自动转为 WorldRecord。
- 具有完整文明和独立规则的空间可由作者手动创建为独立世界，并用既有通道表达联系。不要自动转换或复制秘境。
- 势力继续有一个所属世界；跨世界分部复用既有独立势力记录与分支/附属关系。不得通过本次 UI 修改把 worldId 改为数组。
- 人物为全项目同一份档案。出生地、所在地、身份和行踪是关联，不能切换世界就复制或移动整份角色档案。
- 世界历史复用既有时间线事件关联，不能另建无关联的第二套历史时间轴。
- 总纲规则与本地规则的差异由作者表达，本次不实现自动继承、自动优先级推断或冲突裁决。

## 4. 页面结构与视觉要求

侧栏“世界资料”显示名改为“世界管理”；保持原 editor type、稳定 tab ID 和路由。世界观总纲、地图册、修炼体系仍保留已有入口。

世界管理页采用“世界列表 + 当前世界内容”的布局：

1. 顶部显示“世界管理”、真实世界数量和“新建世界”。说明控制在一行：“为每个世界维护介绍、组成与跨世界联系。”
2. 左侧世界列表：搜索、名字、可选的一行简介、清楚的选中态。可折叠，折叠后保留明显展开按钮。长名称截断但可查看全名。
3. 主区顶部始终显示当前世界名与“编辑世界介绍”；切换世界后默认进入“世界介绍”。页面面包屑为“故事设定 / 世界设定 / 世界管理 / 世界名”。
4. 世界内部使用紧凑的分区导航，内容主区可滚动。窄窗口分区导航可横向滚动或换为可访问的选择器，不堆出三层常驻侧栏。
5. 世界介绍以阅读为主，编辑时进入同一世界的表单；保存后回到本世界介绍，不跳到其他世界或项目首页。
6. 使用现有浅纸色/墨绿主题与深色 token，保留圆角。不要加入装饰性宇宙背景、巨大封面占位、虚假图表或随机图标。
7. 有限文字块采用合理阅读宽度；简介、背景与组成摘要有清楚层次，不能把全部内容挤成表格或大量等尺寸卡片。

## 5. 世界介绍页内容与字段映射

优先使用已有字段，不为看起来丰富而新建多个重叠字段。

| 页面内容 | 来源 | 规则 |
| --- | --- | --- |
| 世界名称 | WorldRecord.name | 沿用原校验与稳定 ID |
| 一句话介绍 | summary | 未填写时显示真实空状态 |
| 世界背景与介绍 | background | 用于时代、文明、环境、特色、主要矛盾等自由内容；不强制全填 |
| 补充说明 | notes | 保留旧内容，不自动拆字段或重写 |
| 组成摘要 | 当前世界关联数据 | 显示实际数量及少量名称预览，点击进入对应分区 |
| 跨世界联系 | 原通道/关联 | 显示对端世界与通行条件摘要，无联系则明确为空 |

背景输入框可提供写作提示：“这里是什么地方？有什么独特规则或文明？主要矛盾是什么？”提示只做 placeholder/帮助文字，不能写入实际内容。

组成摘要至少覆盖势力、秘境、地图、本地规则、相关人物、历史事件。数量按真实记录和现有去重语义计算：同一人物多个身份不应误算多个人物；未归属内容不计入当前世界。

介绍页空状态应允许“编辑世界介绍”和“添加势力/秘境”等直接动作，不要求先写完介绍再进入其他分区。已有世界的 background/notes 必须完整可读，不能只展示 summary。

## 6. 各分区行为

### 势力

默认仅展示当前世界势力，保留类型、介绍、驻地、控制范围、成员与关系编辑。新建表单明显显示所属世界。跨世界关系必须显示对方势力及所属世界，不能让它看起来像本地势力。

### 秘境与特殊空间

分区可显示“秘境”，帮助文字解释也可记录遗迹、禁区等特殊空间，类型复用原自定义字段。保留位置、本体地点、入口、进入条件、风险、资源、开放说明、状态及相关势力/人物。开放状态由作者维护，不按电脑时间擅自改变。

### 地图与地点

只展示当前世界已关联地图及其地点。关联现有地图时沿用原影响预览、子地图规则与阻止条件，不能直接改 worldId 绕过校验。全项目地图册仍是统一编辑入口，跨页定位必须传递真实地图 ID，不按名字猜测。

### 本地规则

保留现有规则结构与适用对象关联。明确“本世界规则说明”，可打开总世界观对照；不新增自动继承。禁止把当前世界规则覆盖到总纲文本。

### 人物、历史与行踪

复用原稳定关联和跳转。新建关联前搜索已有记录，不默认复制人物或事件。解除世界关联与删除人物/事件本体应明确区分，并保留现有删除保护。

### 跨世界联系

将现有“通道”分区的可见名称调整为“跨世界联系”，以通道为主要内容，保留原全部字段与方向语义。显示来源世界 → 目标世界、入口/出口、条件及原状态；双向通道使用正确表达。

必须同时正确展示当前世界为来源和目标的关系，按稳定 ID 去重。涉及其他类型的既有跨世界关系可提供跳转，但不要虚构现有契约未支持的关系类型。缺失引用显示明确状态，不用名称临时拼一个世界。

## 7. 新建、编辑与边界行为

- 新建世界沿用原必填规则，其余介绍字段可留空；保存成功后选中新世界并进入介绍页。
- 新建势力、秘境、规则使用打开表单时的明确世界归属。若期间切换世界，不得把旧表单静默写入新世界；使用既有未保存保护或显式关闭确认。
- 保存失败保留输入并显示错误，禁用重复提交；成功后局部刷新当前世界资料，不重置无关筛选或整个项目。
- 项目切换使用现有 lease/session 隔离；旧请求完成后不得污染新项目。
- 删除继续走既有影响预览与阻止条件，不能因新页面而级联删除角色、地图、时间线事件。协调者核对实际仓库语义，不仅相信按钮文案。
- 无世界、仅一个世界、世界无组成项、孤立旧关联、名称重复、长文本、加载失败均有真实状态。
- 只有名字重复不代表同一实体；跨页和保存全部使用稳定 ID。
- 中文/英文、键盘焦点、标签关联、Escape 与关闭行为、窄窗口和深色主题均需覆盖。

## 8. AI 与扩展边界

保留“AI 生成故事设定”作为故事前提/世界观总纲/情节大纲的生成管理入口。它不是世界实体列表，也不能用其三份文档卡片替代世界管理。

本次不新增世界级 AI 写入流程。若未来增加“生成世界介绍/补充势力”，需要单独设计上下文范围、候选预览、作者确认和稳定 ID 写入，不能直接调用旧总纲生成器覆盖资料。

以下列为后续独立扩展，不混入此次验收，也不宣称已经支持：

1. 多套修炼体系及世界与体系绑定：涉及角色等级 ID、迁移和跨世界等级表达。本次保留项目单套体系，不生成假的世界专属选择器。
2. 世界父子层级、依附关系与循环校验：本次世界列表保持平级，世界包含多个组成项不等于世界必须互相嵌套。
3. 秘境与独立世界的结构化链接或升级转换：本次不自动转换，后续需保留全部引用及可审查的迁移。
4. 跨世界统一势力本体、多地分部的全新数据模型：本次沿用已有势力关系方案。

这些限制只限定本次实现范围，不表示产品永久只能用单套体系或平级世界。

## 10. 必须提供的验收证据

使用临时测试项目构造两个世界 A/B，各有不同的势力、秘境与介绍，另有 A→B 通道、跨世界势力关系、多个世界关联的同一人物和一个未归属地图。样例仅在测试环境，不导入用户项目。

验证：

1. 打开管理页 → 选择 A → 阅读介绍 → 打开 A 势力/秘境；B 数据不混入。
2. 切换 B → 默认 B 介绍 → 展示 B 数据；B 可以看到以自己为目标的通道。
3. 在 A 新建秘境 → 保存读回 worldId=A；失败保持表单；切项目和切世界不串写。
4. 编辑世界背景后重新载入，原 ID 与所有关系不变，未编辑字段不丢失。
5. 人物/历史点击打开原档案或原事件；重复身份不增加人数，不新增同名实体。
6. 地图归属更改与删除仍经过实际影响校验；被阻止操作不能显示成功。
7. 介绍、背景、势力、秘境原有内容均可访问；旧项目无需手动整理或迁移即可打开。
8. 侧栏折叠、窄窗口、长名、长文、空项目、加载失败、英文和深色主题均可用。

交付至少包含：介绍页、势力页、秘境页、跨世界联系页的截图；受影响浏览器/仓库测试及类型检查的实际命令和结果；改动文件；数据未迁移的证据与剩余限制。测试脚本以当前 package.json 为准，不凭空编造命令。

不接受：仅改入口名称；为截图写入假数据；移除旧分区；把所有世界介绍堆进总纲；按名称关联；AI 自动填满空状态；以别的任务旧测试结果替代最终合并验证。
