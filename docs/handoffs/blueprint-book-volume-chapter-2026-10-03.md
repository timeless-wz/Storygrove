## 3. 用户界面

```text
章节蓝图
├─ 全书总纲
├─ 第1卷（箭头负责折叠）
│  ├─ 本卷卷纲
│  ├─ 第1章 章名
│  └─ 第2章 章名
└─ 第2卷
   ├─ 本卷卷纲
   └─ 第N章 章名
```

原侧栏独立“情节大纲”入口撤除。基础设定总览中的相关链接改为“全书总纲”，直接定位章节蓝图的总纲视图。工作流完成跳转、Agent 结果入口及旧 synopsis 链接都定位同一总纲，不复制文档。

左侧固定“全书总纲”，其下卷和章节；每卷固定“本卷卷纲”，空卷也可编写。点击卷标题可打开卷纲，箭头只折叠；事件不能互相冒泡造成双操作。章节搜索不让总纲和卷纲消失，可标明匹配章数。

右侧根据选中对象显示总纲、卷纲或原细纲编辑器。显式 selection 使用 book / volume(volumeId) / chapter(chapterNumber) 联合类型，不用特殊章号 -1、0 冒充总纲。

切换前有未保存内容时沿用可靠保存/放弃保护；保存失败停留原对象。记住有效选择，项目切换清理旧选择。卷改名不丢卷纲，稳定 ID 不变。

继续使用现有主题、圆角、紧凑工具栏。窄窗口允许折叠目录，长文区域可读；不新增全局三级常驻侧栏。

## 4. 三层新增内容

### 全书总纲

承接原 synopsis 全部原文，维护：故事主线、核心矛盾、人物总体成长、主要转折、高潮、结局方向、各卷承担的剧情任务。

初次打开旧项目不得自动拆解或重写原文。以原文编辑为基础，提供这些内容的可选写作模板/提示；模板只在作者主动插入时写入。各卷任务的正式详细内容存在各卷卷纲，总纲页可以展示其只读摘要与跳转，不维护第二份可编辑副本。

保留原手写、AI 生成、续写、来源保护等能力；原按章范围生成的大纲作为兼容模式标识，不能擅自把 chapter range 当作 volume range。

### 分卷卷纲（必须新增完整内容能力）

每卷可独立编写以下分区，允许留空或自由补充，不强迫作者先填满：

1. 本卷定位与承担的全书任务。
2. 开卷状态与本卷目标。
3. 主要冲突、对立力量与关键限制。
4. 主要人物及本卷变化。
5. 关键事件、阶段推进与重要转折。
6. 本卷高潮、结果与代价。
7. 伏笔的引入、推进与计划回收。
8. 卷末人物/世界状态与下一卷衔接。
9. 预计篇幅、章节安排与作者指导。

这九项是规划内容，不是修改正式角色/世界状态的命令。卷纲中的人物变化和伏笔安排属于计划，不能直接提交角色状态或正文伏笔事实。

采用可保留全文的 Markdown 权威，分区可用标题模板与编辑器导航实现，避免结构化表单强制丢弃原自由文本。卷名及排序继续复用原卷记录。章节实际列表从真实 volumeId 读取，预计章数与已有章数分别展示，不自动移动章节。

### 每章细纲

保留现有 v2 内容、分镜、导入编辑和写作入口；新增可编辑的“本章承担的卷内任务”“承接内容”“预期结束变化”等规划表达。

优先通过 v2 现有可扩展分区/字段条目承载，使用稳定语义标识并与原字段兼容，不造第二份章节细纲表。不把计划结束变化写入 notes、正式人物状态或定稿记录。

卷纲读取、保存、候选与批量提交走类型化 IPC、项目 session 和主进程仓库，不在 localStorage 存正式内容。保存使用 expectedRevision；新建期望不存在，冲突返回明确结果，不盲目覆盖。

总纲并发保护必须覆盖所有写入路径：手工编辑、旧 core update、原大纲生成、导入。若采用 hash CAS，所有提交在同一事务内核对预期 hash。不能只给新页面加锁却让旧接口绕过。

- 升级不改 synopsis 原文，不自动生成卷纲。旧卷纲/摘要若已有相同含义字段，契约明确复用或无损迁移，不隐式覆盖。
- 旧卷和章 ID 保留。不得根据章号范围或同名卷猜归属。
- 旧蓝图 volumeId 缺失当前兼容默认卷，维持既有语义，不把所有旧章节突然移到“未归卷”。非法/失效引用需可见提示和显式修复；若新增未归卷能力，要在契约中明确 null 与缺省的差别。
- 正文的显式归卷、drafts.blueprint_chapter_number 与蓝图目录分别处理。重排规划卷不能自动改正文归卷或稿本绑定。
- 多章生成使用全书唯一章节号，不能各卷从 1 重新编号。新章号分配由仓库验证，不能复用已占用号覆盖记录。

### 删除与清空

删除卷必须预览卷纲及子章影响，默认保留细纲与正文，要求明确迁移子章到目标卷或保留卷以免孤立。不要本次悄悄引入级联删章。

现有“清空全部蓝图”操作必须说明清理范围；不能随新总纲/卷纲加入而扩大成清空全部规划。总纲、卷纲、章细纲清空分别确认。用户正文和定稿事实不受影响。

## 6. 三层 AI 工作流（必须实现）

### A. 编写/改进全书总纲

复用原大纲生成能力和来源保护，入口在全书总纲页；区分完整生成与基于现有内容改进。保留旧按章范围续写能力，但不把现有检查点冒充新分卷流程检查点。

新的交互默认产出候选，预览差异并确认后写入。如复用原命令会直接保存，先抽离生成与提交边界，不能套一层“预览”却已改正式内容。兼容旧命令需明确保留其原行为，不能悄悄绕过新入口确认。

### B. 从总纲规划分卷

输入：冻结的全书总纲、篇幅目标、作者分卷数量/偏好和既有卷摘要。输出：拟新增或明确选中更新的卷名、定位、剧情任务、关键转折、卷末衔接及预计章节。

先展示完整候选列表，作者可编辑、选取。确认后原子创建所选卷及各卷卷纲；取消不创建空卷。已有卷按 ID 明确选择更新，默认保留，不按同名合并。

允许只为现有某卷生成/补充卷纲：输入全书总纲、该卷已有稿、相邻卷相关摘要及作者指导，输出该卷候选，不改其他卷。

### C. 从卷纲规划本卷章节

输入：全书总纲、当前卷完整卷纲、相邻卷衔接摘要、当前卷既有章节摘要、作者范围要求。输出本卷章节安排候选，包含章名、卷内任务、关键事件、承接与结束变化。

确认后走现有蓝图提交边界和新增来源记录，明确 volumeId。只是生成章节安排时不得伪称已生成完整 v2 细纲；每章可再执行“展开细纲”，产出符合现有 v2 契约的分区与分镜候选。

原已有人工/导入细纲默认保护。针对已有章的改进只提供候选 diff，不能以重新规划为由覆盖正文、作者指导或正式细纲。角色候选、关系等沿用既有审查边界，不通过章纲生成直接写角色。

### 共同要求

- 全部接入现有工作流引擎、模型选择、项目 lease、运行进度、取消和错误记录；不自建第二套后台队列。
- 明确操作范围：全书/本卷/指定章节。不能从单卷按钮默默改全书。
- 冻结输入；提交时重新检查总纲、卷纲、章版本、归卷和所用来源。变化则保留候选并要求重新生成或重新审查，不误写新事实。
- 候选与来源应持久化，刷新/重启后可恢复；损坏或旧 schema 提供错误，不自动升级解释成正式内容。
- 批量提交事务、稳定 operation ID 和幂等检查防止重试重复创建卷/章；部分生成失败可以查看已完成候选，但不能报告整批正式保存成功。
- 长任务分批，不全书一次性装载所有细纲；列表只读轻量摘要，目标章需要时显式读完整细纲。
- 生成完整卷纲不强制修改总纲；生成章细纲不强制改卷纲。上级缺失时提示补充或允许有标记的手动编辑，不禁止手写。

## 7. 上下层衔接检查与变化提示

必须提供“检查本卷与总纲衔接”和“检查本卷章节与卷纲衔接”。输出问题、引用来源、涉及卷/章、建议修改；只产出检查报告，不直接重写内容。

规则可检查归属/来源版本/缺少衔接等确定性问题，AI 检查剧情目标、冲突推进、人物计划变化与收尾衔接。二者分开标识，AI 判断不是强制错误。

上级保存后，根据来源快照标记下级“上层已变化，建议检查”。没有快照的旧内容显示“尚未建立来源关联”，不能假称过期或已同步。不自动重跑整书。

手动编辑的下级内容仍可运行检查；检查完成必须绑定被检查的版本，源内容再变化后不得继续显示“当前已检查”。不通过一次检查自动重置来源为最新而隐藏实际差异。

## 8. 下游写作与导入导出

正文生成继续读取总纲与章细纲，并新增当前蓝图明确所属卷的卷纲/相关摘要。通过实际 blueprint volumeId 定位；无卷纲时保持旧写作链可用，不编造卷纲、不按正文卷或章号推断。写稿/审稿/修稿接入位置逐条检查，记录实际覆盖，不宣称所有模型流程自动获得新内容。

卷纲属于计划材料，与角色事实、正文定稿分开标记。冻结卷纲来源用于写作追溯；不能把预计状态写成已发生事实。不要把全书所有卷纲和所有章全文塞入提示词。

总纲导入导出沿用原 Markdown；卷纲新增独立 Markdown 导入、预览、确认、导出。现有章细纲导入导出保持逐字保真契约。

整体规划导出应包含版本清单、总纲、卷与卷纲、章归属、现有章细纲；明确不包括正文。若支持整体导入，必须做实体映射、冲突预览和原子提交；本轮最低要求独立卷纲导入与完整规划导出，不能放一个无效的整体导入按钮。

## 10. 验收与交付

必须用临时数据库/临时项目。至少构造：有长总纲的旧项目、两个卷、人工导入细纲、无卷纲的卷、空卷、显式独立正文归卷、已绑定蓝图的多版草稿、并发修改和失败场景。

验证矩阵：

1. 升级前后总纲和细纲原文一致，卷/章/草稿绑定不变；迁移可重复运行，失败不半迁移。
2. 打开总纲/卷纲/细纲都能编辑保存并重启读回；切换失败不丢输入。
3. 总纲规划分卷：取消不创建卷，确认创建卷及卷纲，重试不重复；同名不误合并。
4. 卷纲规划章节：章号唯一、归属正确，已有细纲不覆盖；候选不是正式细纲。
5. 展开章节细纲：结果符合 v2、场景原文保持、revision/hash 正确；不写 notes 或改正文。
6. 生成期间上级或归卷改变：提交被阻止，候选可恢复；旧项目无快照提示准确。
7. 上下层检查只写报告，引用准确，不改剧情；版本变化后报告状态更新。
8. 写作上下文明确包含当前卷材料；无卷纲兼容旧行为，绝不混入其他卷或把计划当已发生事实。
9. 总纲旧入口和新入口编辑同一记录；基础设定/工作流结果都能定位正确层级。
