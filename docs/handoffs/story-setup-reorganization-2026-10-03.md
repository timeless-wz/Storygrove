## 1. 要解决的问题

目前“创作参数”同时放基础参数、故事构想和写作规则；“世界观”文档与“世界”资料分散在两个一级组中；情节大纲归在故事设定，世界及地图却归在创作规划。初始主角构想与正式角色档案容易混淆。故事架构总览的生成入口藏在小图标中。

整理后的作者路径应清楚：确定方向 → 编写故事前提和设定资料 → 规划全书剧情与章节 → 写正文。允许跳过和自由访问，不增加强制流程。

- 不修改用户项目数据库，不访问母稿进行写入，不批量移动实际资料，不迁移数据库表或字段。

## 4. 页面分区与文字规范

### 创作方向

沿用原 NovelConfigEditor 的同一份配置、同一保存和生成逻辑。使用三个页内分区标签或锚点导航；推荐单页锚点，避免切换时卸载表单导致输入丢失。窄窗口允许导航换行，表单由多列自然变为单列。

| 分区 | 原功能 / 字段 | 修改要求 |
| --- | --- | --- |
| 基础信息 | 写作语言、题材、受众、视角、总章数、每章字数及现有其他基本字段 | 全部保留，目标字数计算不变 |
| 初始构想 | coreOutline | 标题改为“故事构想”；提示“用于确定创作方向和生成输入，详细剧情请维护情节大纲” |
| 初始构想 | worldSetting | 标题改为“背景构想”；提供打开世界观总纲的明确入口 |
| 初始构想 | goldenFinger | 标题“主角优势 / 核心卖点”；保留实际内容及原生成行为 |
| 初始构想 | protagonistProfile | 标题“主角构想”；提供打开角色档案入口，不自动新建或匹配角色 |
| 写作要求 | 全局写作要求、文风配置、参考作品 | 保留独立字段，不把它们拼成一个字符串保存 |
| 写作要求 | 高级结构偏好、质量与连续性配置 | 放在分区下方的“高级选项”；默认折叠，原字段与验证保留 |

初始构想顶部显示简短说明：“这里保存创作起点。正式人物、世界与剧情资料请在对应页面维护；修改这里不会自动同步它们。”这描述的是编辑保存边界，不能误写为 AI 后续完全不读取这些输入。

保留“AI 填充配置”、各字段已有 AI 生成、保存、加载与错误反馈。不能因重新分区改变其影响范围；实际生成目标字段、工作流参数和持久化键名不随 UI 改名。

跨页入口沿用既有未保存保护；若当前路径没有保护，需在离开前保存成功或让用户明确选择保留/放弃，保存失败停留原页。不能点击关联入口就丢草稿。

### 状态与术语

- 原创作参数状态当前由 `coreOutline` 或 `protagonistProfile` 非空判断；同样条件下用“已有构想”，不再称“已完成”。不把该判断升级为虚构的完整性分数。
- 无上述构想时可用“待补充构想”，不声称其他基础参数尚未填写。
- 三份文档有内容只代表“有内容”，不代表已确认、已定稿或全部生成成功；候选与正式内容继续区分。
- “世界资料”指结构化世界工作台；“世界观总纲”指原长文档；“地图册”指空间编辑工具。三者互补，不声称自动同步。
- 所有名称调整同步中文/英文显示。建议英文：Creative direction、Story premise、World setup、Worldbuilding overview、World records、Map atlas、Cultivation system、Generate story setup。
- AI 工作流内部仍可叫 architecture；不要做全仓库字符串替换，也不要修改历史日志或用户正文。
