# InkSpire 风格前端重建与功能融合方案

状态：提案，尚未开始实施  
范围：AI-Novel-Writer 的渲染层、界面信息架构和用户交互；不替换项目数据库、领域服务、IPC 或模型服务。  
目标：以 InkSpire 已观察到的产品体验作为**设计与交互参考**，在本项目中重新实现一套独立的小说创作桌面应用。

## 1. 先说明：为什么不是“直接运行抓到的页面”

浏览器抓取到的是发布后的前端产物：HTML 外壳、压缩过的 JS/CSS chunk、字体和图片。它不是可维护的完整源码工程，并且仍依赖原站的认证、API、数据库、文件服务与 AI 服务。

因此本方案不把抓到的 bundle 放进本项目，也不复用原站的登录票据、接口、业务数据、品牌素材或私有资源。我们从中提炼的是：

- 页面层级、布局、卡片、颜色、间距、动画与画布交互；
- 书架、项目工作台、设定、画布、编辑器与 AI 面板之间的产品路径；
- 用户在自己正常可访问页面中可见的功能行为。

所有实际组件、样式、状态和数据连接均在本仓库重新编写，并使用本产品自己的名称、图标、文案和已获授权的素材。

## 2. 成功定义

完成后，用户应感觉这是一个有完整小说创作流程的现代桌面产品：从书架挑选项目，进入沉浸式创作台，在不离开项目的情况下查看章节、设定、角色、剧情画布、知识资料和 AI 助手。

同时必须保持以下已有能力的行为不变：

- 本地项目与 SQLite 权威数据；
- 项目会话隔离、审批/确认边界、草稿与已发布内容的可编辑性；
- Vditor 正文编辑、保存、未保存提示、版本/审核入口；
- 角色、蓝图、叙事线、时间线、地图与关系图的现有数据；
- 本地 AI、工作流、任务、日志、模型设置、导入和导出。

“视觉接近”不能以静态假页面换掉真实入口为代价。

## 3. 当前工程可复用的基础

| 现有基础 | 当前入口 | 重建时的用途 |
| --- | --- | --- |
| 应用三栏壳 | `src/App.tsx` | 改为新的首页/工作台壳，同时保留可收起、可调整宽度的面板能力。 |
| 布局状态 | `src/stores/layout-store.ts` | 继续作为首页、创作、资料、角色、AI、专注模式等可测试状态的唯一来源。 |
| 项目侧栏与树 | `src/components/panels/Sidebar.tsx`、`sidebar/ProjectTree.tsx` | 换为新视觉与分组方式，仍调用既有打开文件逻辑。 |
| 项目总览 | `src/components/pages/ProjectOverviewPage.tsx` | 演进为项目仪表盘/创作主页，继续展示真实章节、字数、地图、时间线数据。 |
| 正文编辑器 | `src/components/editor/VditorProseEditor.tsx` | 作为新创作台正文区域，不更换正文存储和保存协议。 |
| 无限画布 | `@xyflow/react`、`StoryTimelineView.tsx`、`RelationshipGraph.tsx` | 统一节点、边、工具栏、小地图、选择态与侧栏，不重新发明画布内核。 |
| 本地数据边界 | renderer services、Electron IPC、repositories | 保持 renderer 不直接访问数据库；页面只通过现有 IPC/服务获得真实数据。 |

## 4. 目标信息架构

```text
书架首页
├─ 最近项目 / 项目封面 / 写作进度
├─ 新建、导入、打开项目
└─ 项目快速恢复

项目创作台
├─ 顶部：项目切换、全局搜索、保存状态、AI、设置
├─ 左栏：概览、正文、剧情、设定、角色、资料
├─ 中央：当前工作面（仪表盘 / 编辑器 / 画布 / 表单）
├─ 右栏：上下文、关联资料、AI 助手、检查结果
└─ 底栏：任务、日志、模型运行状态

设定与规划
├─ 章节蓝图、剧情线、故事时间线
├─ 角色档案与关系图
├─ 世界观、地点和地图册
└─ 资料中枢、知识检索、审核
```

现有“首页、创作、资料、知识库、角色、运行支持”的功能归属保持有效；此次调整的是入口呈现和工作面编排，不能制造第二套相同的数据页。

| AI 侧栏 / 操作面板 | 现有 Agent 与输出面板的新外观 | `AIPanel`、`AIOutputPanel`、workflow store | 不模拟原站模型、订阅或远端接口。 |

## 6. 视觉与交互规范

### 6.1 设计原则

1. **层级优先。** 首页是书架，项目内是创作台；工具不应平铺为几十个同级按钮。
2. **内容优先。** 正文和画布占中心最大区域，信息栏默认是辅助而非主角。
3. **低干扰深色质感。** 使用克制的深浅面、细边框、少量主色和明确状态色；不能以低对比度牺牲可读性。
4. **操作可发现。** 高频动作直接出现在已选卡片/节点/章节上；低频动作进入上下文菜单。
5. **同类工作面一致。** 卡片、标签、弹窗、空状态、加载态、工具提示、键盘焦点和危险操作采用同一套组件规范。

### 6.2 设计令牌

在 `src/index.css` 的现有语义色基础上补齐独立令牌；组件只能引用语义令牌，不新增随意的硬编码颜色。

```css
--surface-canvas        /* 最大背景面 */
--surface-raised        /* 卡片、面板 */
--surface-overlay       /* 弹窗、浮层 */
--border-subtle
--border-strong
--text-primary
--text-secondary
--text-tertiary
--accent-primary
--accent-soft
--focus-ring
--shadow-card
--shadow-overlay
--radius-card
--radius-control
--space-1 ... --space-8
```

不同主题/皮肤必须继续经语义令牌适配，不能让新界面只在默认深色主题可读。

### 6.3 关键交互规则

- 项目卡点击进入项目；卡片内的“继续创作”直接定位到可写章节。
- 左栏切换工作域不丢失当前未保存正文；打开的编辑标签仍由 editor store 管理。
- 单击画布节点选择，双击打开编辑；删除、关系变更和支线创建走已有确认/持久化路径。
- 右栏根据当前工作面显示相关上下文；AI 面板只在用户请求时展开。
- 专注模式隐藏辅助栏而不卸载编辑器或改变项目数据。
- 所有图标按钮提供可见或可读的名称、悬浮提示与键盘焦点。

## 8. 分阶段实施计划

### 阶段 0：参考归档与验收基线

**产出**：受控的 `docs/reference/inkspire/` 参考清单（截图、页面说明、交互笔记），不保存 Cookie、HAR、Token、私人正文或 API 响应。

**工作**：

- 对每张用户提供截图标注页面名称、可见状态、用户动作、可复用设计语言；
- 建立“参考体验 → 我方功能 → 现有入口”的映射表；
- 保存当前关键页面的截图和浏览器测试基线；
- 列出不可参考的品牌资产、文案、后端接口与账户能力。

**验收**：每个要实施的页面都拥有至少一张参考图、一个真实数据入口和至少一个可测试用户动作。

### 阶段 1：设计令牌和通用组件

**产出**：令牌、卡片/按钮/弹窗/标签/空状态/加载骨架的一套一致外观。

**工作**：

- 补齐颜色、间距、圆角、阴影、字体和焦点令牌；
- 先替换现有通用 UI 的视觉皮肤，不改 IPC 和 store；
- 为深色、浅色和已有皮肤检查文本、状态色与焦点对比度。

**验收**：现有主题文本对比度测试保持通过；键盘操作仍可见焦点；不引入固定品牌图片或第三方字体文件。

### 阶段 2：书架首页和项目入口

**产出**：新的 `LibraryHome`，展示真实最近项目、项目状态、继续创作和新建/导入入口。

**工作**：

- 将当前首页从工具侧栏提升为书架主工作面；
- 使用真实 `recentProjects`、当前项目和草稿统计；
- 完成无项目、加载失败、项目缺失、项目关闭等空状态；
- 保留快捷键、项目选择器、打开和关闭时的未保存确认。

**验收**：项目卡可打开正确项目；“继续创作”进入真实可写章节；关闭项目不会丢失未保存内容。

### 阶段 3：项目工作台和正文创作

**产出**：新顶部栏、领域导航、章节导航、中央编辑面和按需上下文栏。

**工作**：

- 以 `App.tsx` 的三栏能力为基础调整编排，不替换 `layout-store` 的状态语义；
- 将 `ProjectTree` 变成清晰的“正文 / 规划 / 设定 / 资料”分组；
- 将现有 `EditorArea` 的标签、保存、字数、审核与专注模式装入新创作面；
- 让右栏基于当前 tab 显示真实蓝图、角色、世界观、任务与 AI 入口。

**验收**：打开、切换、保存、关闭、丢弃、专注模式、AI 面板和项目切换均保持原有行为；不允许静态占位内容替代数据。

### 阶段 4：剧情、角色和地图画布统一

**产出**：一套一致的画布壳、节点视觉、操作工具栏、检查器和小地图样式。

**工作**：

- 复用 `@xyflow/react`；仅提取共享的视觉和交互部件；
- 分别接入故事时间线、角色关系图和世界地图，不把三种领域数据混成单一表；
- 把新建、连线、选择、编辑、删除、缩放、拖动、支线等现有行为逐条接回；
- 对窄窗口、长节点标题、空画布、多选、键盘删除和错误恢复做针对性处理。

**验收**：节点/边/位置在重启后仍正确；关系线中心锚点不漂移；时间线主线和支线语义不改变；现有浏览器画布测试通过。

### 阶段 5：设定、资料和 AI 工作面

**产出**：角色、世界观、章节蓝图、资料中枢、知识库和 AI 的统一页面语言。

**工作**：

- 先替换容器、标题、分段、详情抽屉和卡片；保留领域编辑器；
- 将审批状态、来源、冲突、候选与已确认显示为明确、可理解的状态；
- 让 AI 操作显式展示输入范围、运行状态、错误和结果去向；
- 继续遵守“AI 提案不直接覆盖作者内容”的现有产品边界。

**验收**：所有进入现有编辑器、审核、任务和资料页的路径仍可用；确认/删除等高风险动作仍有原有保护。

### 阶段 6：收口、迁移和发布前验证

**产出**：移除已弃用的样式壳，保留迁移说明和可回退版本。

**工作**：

- 逐页删除只有在新页面完成行为验收后才不再使用的旧样式；
- 检查所有本地化文案、截图、键盘导航、缩放和主题；
- 运行针对性单元/浏览器测试、类型检查、构建和人工桌面烟测；
- 增加新书架、工作台和画布的关键行为测试，而不是仅检查 CSS 类名。

**验收**：新 UI 能打开真实项目、编辑并保存章节、管理资料、使用三类画布、执行 AI 工作流；应用重启后数据没有丢失；安装包验证另按发布流程进行。

## 9. 数据和安全边界

```text
新界面组件
   ↓
现有 Zustand store / renderer service
   ↓
既有 Electron IPC（携带项目会话）
   ↓
领域服务与 repository
   ↓
项目 SQLite / 本地 LanceDB
```

- 页面组件不得直接打开 SQLite 或读取别的项目路径。
- 项目切换必须继续使用完整项目路径/会话身份，而非假定全局 `main`。
- 参考截图和前端资源不进入产品安装包，除非确认有权使用且已替换为我们的资产。
- 不从抓取记录导入 Cookie、令牌、认证头、用户数据或接口响应。
- 所有删除、覆盖、审批和发布行为必须保持现有确认及审计边界。

## 10. 测试策略

每个阶段必须同时有“数据正确”和“用户看到的行为正确”两类证据。

| 面向用户的场景 | 自动验证 | 人工验证 |
| --- | --- | --- |
| 书架项目卡 | store/组件浏览器测试：项目身份、打开、空状态 | 打开最近项目、切换项目、关闭项目后的显示。 |
| 正文工作台 | 浏览器测试：tab、dirty、保存、关闭/丢弃、专注模式 | 输入正文、切换资料、打开 AI、缩放窗口。 |
| 画布 | 浏览器测试：选择、拖动、连线、删除、位置持久化 | 缩放、平移、多选、小地图和长文本节点。 |
| 领域入口 | 现有项目/会话/IPC 测试继续运行 | 从每个新入口实际抵达正确的真实功能页。 |
| 视觉质量 | 令牌、文本对比度、关键截图回归 | 深浅主题、中文/英文、常见屏宽和高 DPI。 |

通过构建不等于通过界面验收；发布前还要进行真实 Electron 启动与安装包烟测。

## 12. 第一轮执行顺序

在收到首页和创作台参考图后，第一轮只做以下可独立验收的范围：

1. 建立新设计令牌和通用卡片/按钮/面板；
2. 实现书架首页和真实项目卡；
3. 将项目总览改造成新的项目仪表盘；
4. 不改正文数据与保存逻辑的前提下，为编辑区套上新的创作台外壳；
5. 用浏览器测试证明“打开项目 → 继续创作 → 编辑 → 保存 → 重启后仍可读取”。

画布、设定和 AI 面板在第一轮验收后继续推进。这样每一轮都有可用产品，不会因一次替换整个前端而失去已有创作能力。
