# 灵感速记（灵感收集）数据结构与交互提案

状态：**提案，本任务未实现任何代码或数据库变更**。本文只提交数据结构与交互建议，供决策后再排期。
范围：资料与故事记忆页面的作者侧速记能力。不新增第二套资料真相来源，不改变现有事实、来源、候选与审核边界。

## 1. 为什么需要单独一类实体

参考产品的「灵感墙」把作者随口记下的碎片与设定资料放在同一个视觉层级里。本项目的资料语义不允许这样混放：

- 正式事实（`StoryFact.status = 'confirmed'`）、候选资料（`StoryFactCandidate.reviewStatus = 'pending'`）、来源（`WorkspaceSource` + 批准快照）已经各自有明确的生命周期与权威状态；
- 灵感是**尚未被作者判断**的自由文本，它既没有来源片段，也没有权威状态，更没有可核对的行号与快照。

因此灵感必须是一类独立实体：**速记 → （作者显式晋升）→ 候选资料 → （作者确认）→ 正式事实**。灵感本身永远不是事实，也不会因为它存在而被检索或注入正文。

## 2. 数据结构建议

```ts
/** 作者的项目内灵感速记；只在当前项目可见。 */
export interface InspirationNote {
  noteId: string
  projectId: string
  /** 自由文本，唯一的内容字段。 */
  body: string
  /** 作者自定义标签，用于分组与检索。 */
  tags: string[]
  createdAt: string
  updatedAt: string
  /** 归档（软删除）；不物理删除，便于追溯。 */
  archivedAt?: string | null
  /**
   * 晋升轨迹。一旦晋升为候选资料，记录目标候选，避免同一条灵感被重复提拔；
   * 原文仍然保留，且不被视为事实来源。
   */
  promotedCandidateId?: string | null
  promotedAt?: string | null
}
```

字段取舍：

- 不含 `authorityStatus`、`confidence`、`provenance`：灵感没有权威可言，也不该被赋予可信度分值，否则会被读成候选资料。
- 不含 `entityType`：类型判断发生在晋升为候选的时刻，由作者填写。
- `promotedCandidateId` 只是外键引用，不复制候选内容；被引用的候选由故事资料中心维护。

## 3. 与其他数据的关系（边界）

| 关系 | 规则 |
| --- | --- |
| 故事资料中心 | 灵感不出现在任何队列、计数或筛选中；晋升后由候选队列接管。 |
| 来源与批准快照 | 灵感没有来源文件与快照，不参与「来源快照待复核」的统计。 |
| 知识检索（kb） | 灵感默认不入库；若作者显式加入，需与项目文档同一入口并单独标记语料类型，避免被当成章节语料。 |
| 正文与生成上下文 | 灵感永不进入；只有作者确认后的正式事实才可能进入。 |
| AI 读取 | 默认不读。若未来允许模型读取灵感用于提示，必须单独授权并逐条可见。 |

## 4. 交互建议

### 4.1 入口与速记

- 单一速记输入框（多行，Enter 保存，Shift+Enter 换行），空内容不可提交；提交后保留焦点以便连续记录。
- 标签输入支持已有标签补全，不清空作者已输入的正文。
- 保存位置与反馈明确：提交成功显示「已记入灵感速记」，不弹确认框。

### 4.2 列表与筛选

- 时间倒序，按「今天 / 本周 / 更早」分组。
- 搜索只匹配正文与标签；不搜索其它实体。
- 筛选：全部 / 未晋升 / 已晋升 / 已归档，各显示真实计数。
- 不使用无法从真实数据计算的指标（例如「灵感质量」「命中率」）。

### 4.3 每条灵感的动作

- **转为候选资料**：跳转到故事资料中心并预填候选表单（类型、名称、摘要来自作者在跳转时的输入），提交后仍走既有 `story-data:list-candidates` 待审队列，由作者确认。晋升后原文标记「已晋升」，不再出现在未晋升筛选里。
- 打标签、编辑、归档（归档需二次确认，且可恢复）。
- 不提供「直接写入正式资料库」的动作。

### 4.4 空状态

必须说明真实路径，不填充占位卡片：

1. 在上方输入框记下第一条灵感；
2. 从母稿扫描或模型候选转化而来的灵感，需要在故事资料中心确认后才会成为设定；
3. 归档的灵感可以随时恢复，不会被删除。

## 5. 待决策事项（本任务不擅自决定）

1. **存储位置**：建议在项目库新增 `inspiration_notes` 表（项目隔离、可迁移、不污染文档列表），代价是需要数据库迁移与仓库/服务/IPC 三层实现；
   备选是写入受控目录的单一项目文档（零迁移，但会出现在项目文档列表并可能被误加入知识检索）。此决定需要 ADR，且必须与数据库负责人确认。
2. **是否允许模型读取灵感**：默认否。
3. **晋升是否产生审批记录**：建议复用既有作者确认路径，不新增审批概念。
4. **命名**：使用「灵感速记」或「灵感收集」，不使用「作品记忆」「真相档案」等会与事实库混淆的名称。

## 6. 未来实现的验收要点（示例）

1. 空状态包含上述三条真实路径；空内容不可提交；归档后可恢复。
2. 晋升只通过既有候选通道发生，且原文保留 `promotedCandidateId`。
3. 灵感不出现在故事资料中心的候选/正式/废止任何队列与其计数中，也不出现在来源权威状态统计里。
4. 未被显式加入检索时，灵感不出现在知识库的已收录语料列表中。
5. 新表迁移在旧项目上可重入，删除项目时随项目数据一并清理。
