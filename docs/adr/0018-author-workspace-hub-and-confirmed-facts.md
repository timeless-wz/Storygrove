# 创作资料中枢与外部母稿只读事实流

长篇小说创作母稿采用双层事实模型：外部 Markdown 资料目录是作者的草稿与素材母本，只读接入；项目 SQLite 数据库是正文写作与模型推理的唯一正式运行事实源。系统严禁向外部目录进行任何回写、修改、重命名、移动或删除。项目删除或解除绑定绝不级联删除外部母稿文件。

外部母稿到系统事实的流转遵循单向严格审批流：扫描 -> 结构解析与哈希索引 -> 候选预览 -> 作者显式确认 -> 事务原子提交。未经作者确认的内容（如从 `05_人物与关系.md` 提取的角色、从设定文档提取的规则）仅保存在中枢候选队列中，严禁静默写入 `characters` 角色名单或正式设定规则库。

角色事实严格继承 ADR 0007 规范：候选角色经作者在审批弹窗确认后，必须通过 `CharacterRosterRepository.commit` 以 `manual_edit` 意图提交，原子更新 `characters` 表并重构 `characters_arch` 图谱投影，绝不绕过角色领域层直接操作底层表。

中枢设定规则实行四级权威划分（已确认 confirmed、候选 candidate、后台 background、废案 deprecated）。废案（deprecated）具有最高排除优先级，严禁进入正向提示词与上下文注入；候选规则（candidate）注入上下文时必须带有显式 `[待确认/候选]` 警示前缀；后台设定（background）按需调用，不默认全量下发。

章节上下文装配实行确定性 13 阶段流水线，在字符预算上限内按阶段优先级装配材料。当内容发生外部变更导致哈希不一致时，系统给出陈旧警告但不阻塞当前创作；超出预算截断时明确记录被略过的阶段与原因。
