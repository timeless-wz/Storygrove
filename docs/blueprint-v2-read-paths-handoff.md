# 章节蓝图 v2 读取路径集成交接

本分支按冻结的 `docs/blueprint-v2-contract.md` 更新章节蓝图的单章读取、列表投影、Agent 读取/提案和跨章节摘要。契约文件未修改，也没有新增字段或 IPC 通道。

## 已处理

- 单章上下文与阅读面板按正文的显式蓝图绑定读取 v2 detail；章节侧栏将正式分镜当作蓝图内容呈现，不再读取旧章节画布卡片作为第二套场景。
- 阅读面板提供完整 Markdown 查看、复制和 `.md` 下载；序列化前调用 `assertNoLossOnSerialize`。
- `read_blueprint` 单章读取完整 Markdown，列表读取返回有界标题/场景摘要；不会将 `notes` 当成蓝图细纲。
- Agent v2 提案以完整 Markdown 解析，按章题、分区和稳定 scene ID 展示字段级差异，并用 base revision 保存；v2 章节拒绝旧式字段白名单写入。
- 章节列表、摘要面板、PlotCanvas AI 和叙事线索候选只保留有界字段与场景标题；PlotCanvas 仍只消费跨章节摘要，不读取分镜正文。
- 分镜内的小标题（如 `###### 时空与环境`）现在留在其所属 scene Markdown 中。
- 角色改名不改写细纲 Markdown，改名后提示用户相关蓝图待核对。
- 旧版外部 Agent 提案审查在发现 v2 时展示完整细纲并禁用批准，避免把 v1 JSON 比较误当作完整 v2 审查。

## 需集成任务处理的契约缺口

1. **旧版列表 IPC 无界**：`db:blueprint-v2-summary-list` 只含 v2 章；调用方为兼容 v1-only 简纲仍需读取 `db:blueprint-get-all`，该通道返回完整 v1 字段后才在 renderer/tool 内截断投影。模型最终载荷已设长度/数量上限，但 IPC 到 renderer 的旧数据传输尚不能严格做到“只获取有界摘要”。需确认是否新增兼容旧简纲的有界列表读取能力；本分支没有另造字段或改冻结通道。
2. **原文 Markdown 的章题间空白不可表示**：验收 fixture 章题行后、首个分区前的空行当前进入 `docPreamble`；§4.2 又规定 `docPreamble` 必须序列化在 `chapterTitle` 前。当前结构化无损自检会通过，但 `serialize(parse(fixture))` 会把该空行移到章题前，字节/换行归一化后仍与原 Markdown 不同。仅靠现有字段无法同时表示章题前文本与章题后的间隔；需集成方调整已冻结语义或授权可选字段。未自行修改契约或更改样例小说内容。
3. **改名待核对标记仅是提示**：没有可承载逐章“角色改名后待核对”的冻结字段/通道，因此当前给出非破坏性提示，不做模糊全文替换，也不能跨重启保留逐章状态。若必须持久标记，请由集成任务先扩展契约。

以上缺口是在实现/测试中发现，故作为集成交接记录；此文件不更改 `blueprint-v2-contract.md` 的冻结内容。
