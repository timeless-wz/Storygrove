# 创作资料来源与 AI 上下文契约

状态：本次实现的来源契约；新增工作流或来源变更时同步更新读取矩阵。
范围：创作资料入口、项目数据库、旧 NovelConfig 兼容层与模型请求上下文。

## 权威来源

| 内容 | 正式存储来源 | 旧字段与优先级 |
| --- | --- | --- |
| 创作方向 | `project_core.creative_direction_markdown`、`reference_works`、类型/细分类型/目标读者 | `global_guidance` 只在作者确认其属于原则且复制保存后成为旧来源；待整理时为参考输入。正式方向有内容时不把旧副本重复注入。 |
| 写作规范 | `project_core.writing_rules_markdown`、`narrative_pov`、`writing_language` | `writing_style` 与执行规则类 `global_guidance` 作为待整理旧内容；正式规范优先。 |
| 故事前提 | `project_core.premise` | `core_outline` 只有在前提为空且该来源仍为 pending 时才可作为参考；前提有内容后正式前提优先。旧字段不自动覆盖前提。 |
| 世界设定 | `project_core.worldbuilding` | `world_setting` 是待整理旧内容；已有正式世界设定后不再平行注入。 |
| 力量体系 | `cultivation_meta.markdown` 与可选等级表；人物个人能力来自人物档案 | 旧 `golden_finger` 仅在对应正式资料为空且来源 pending 时作参考，不能提升为通用机制。 |
| 地点与区域 | `world_map_nodes.description`；`map_id=''` 表示未关联地图 | 不以地图或地图图片是否存在决定地点资料能否保存。 |
| 人物与关系 | `characters`、角色关系/行动线业务表；人物个人能力在该人物档案 | `protagonist_profile`、`golden_finger` 及旧人物文本均为待整理来源。角色表是人物当前事实来源；未来人物变化仍为计划。 |
| 全书/分卷/逐章规划 | Blueprint v2 正文及其 `revision`、`contentHash`、显式章节绑定 | `project_core.synopsis` 按现有蓝图同步契约读写；不以章号推断草稿绑定或卷归属。 |
| 信息与揭露 | `info_entries` 的作者真相/确定状态；`knowledge_records` 的人物或读者认知与揭露计划 | 不从世界设定正文推断知情状态。`undecided` 不得生成成已确认事实。 |
| 素材与候选 | `creative_material_entries`，`entry_kind='material'`，用途、正文状态独立记录 | 候选默认不进入事实上下文；仅明确选中的条目可以作为灵感/计划输入。已采用也不等于已发生事实。 |
| 废案与问题 | `creative_material_entries` 中的 `retired` / `issue` | 废案仅作为禁止重提或审查约束；问题用于审查，不得被模型描述为已修复。 |
| 待整理旧内容 | 原有 `project_core` 字段原文 + `creative_legacy_organization` 的字段/hash/整理状态 | 不删原文。整理状态只对相同内容 hash 有效；字段变化会重新变成 pending。完成归位后旧副本不再参加 AI 上下文。 |

正式内容不会因文件名、段落标题或 AI 判断而自动确认。作者可保留来源文件名和原文标题作为出处；拆分、复制到正式入口、保存和回读后，再显式确认对应旧字段已整理。

## AI 来源选择规则

1. 工作流先声明实际需要的内容类别和实体范围，再读取来源；不能序列化整个 `NovelConfig` 代替选择。
2. 项目正式资料优先于同主题旧字段。相同规范化 Markdown 在一次请求内去重，并在提示词中保留来源标识。
3. 待整理旧内容只在相关正式入口为空时作为“待整理参考”使用；与正式内容冲突时必须服从正式来源并标出冲突。
4. 候选、已采用素材、未来卷章计划都按计划或候选标注，不能作为已发生历史。未定真相继续标为未定。
5. 废案仅进入明确的禁用约束或审查上下文。问题记录仅进入审查上下文。
6. 缺少必要资料、数据库读取失败或内容损坏时，工作流应报错或明确提示；不能静默删除约束。
7. “本次使用资料”必须从该次组装后的模型请求生成，展示真正提交的来源，不使用固定页面清单。

## 字段迁移

迁移只增加 `project_core.creative_direction_markdown`、`project_core.writing_rules_markdown`、旧内容整理台账和类型化素材表，不删除或覆盖既有旧字段。新列默认空，不进行推断式语义搬移。旧配置仍可由“待整理旧内容”查看。素材记录通过 revision compare-and-swap 保存；地点复用原地图节点表；力量体系 Markdown 与等级结构在原 cultivation 模块内保存。

对复制整理采用作者可见流程：选择来源 → 预览原文及推荐入口 → 作者拆分并逐项粘贴 → 保存 → 重新打开回读 → 显式确认整理状态。若目标已有内容、与目标完全相同或部分重叠，均由作者决定合并；本应用不静默覆盖或自动摘要。

## 实际工作流读取矩阵

每项实现须更新本表，列出实际发给模型的来源，而不只是 helper 的候选输出。

| 工作流 | 应读取的正式来源 | 条件来源 |
| --- | --- | --- |
| 生成故事前提 | `GenerateCoreSeedCommand` 读取创作方向、现有正式前提、世界设定、人物架构和力量体系 | 仅在对应正式入口为空时读取兼容旧字段；作者本次步骤指导；输出仍沿用当前故事架构写入行为 |
| 生成人物资料 | `GenerateCharactersCommand` 读取正式故事前提、世界设定、力量体系、角色名单、创作方向、参考作品和结构化篇幅参数 | 作者本次指导；当正式世界/方向为空时，兼容背景/全局要求作为待整理参考；只有正式角色名单为空时，旧主角构想/优势以待整理参考提供；结构化候选仍走现有写入/回读链路 |
| 生成世界设定 | `GenerateWorldBuildingCommand` 读取创作方向、故事前提、现有正式世界设定、人物架构及力量体系 | 相关待整理旧字段只在正式入口为空时以参考语境出现；作者本次指导；截断恢复绑定输入指纹 |
| 字段辅助生成 | `GenerateFieldCommand` 按字段读取对应正式类别；世界/个人优势字段额外读力量体系 | 结果明确属于“初始构想”，不得作为正式事实；保存位置仍沿用原配置字段 |
| 全书总纲候选 | Blueprint 规划读取创作方向、故事前提、世界设定、人物架构、现有总纲及信息/揭露记录 | 素材页显式选中的候选/已采用素材；按候选标记。总纲结果沿用原候选编辑、人工确认及来源快照链路 |
| 分卷与章纲候选 | 读取上级总纲、现有卷/章有界摘要、创作方向、故事前提、世界设定和信息揭露记录 | 章扩展额外读取本章人物档案、力量体系及匹配地点；卷章内容按计划标记并保留人工确认链路 |
| 生成正文 | 读取显式绑定的当前章纲/细纲、相关卷纲和全书摘要、正式世界与人物资料、写作规范、连续性及信息揭露投影 | 只注入与当前章节相关的知情记录和揭露计划；不按章号推断草稿绑定 |
| 修稿/审查 | 当前正文、显式绑定章纲、相关正式世界/力量/地点/人物资料、写作规范及审查目标 | 相关废案作为禁用约束、开放问题用于审查；未定真相保持未定 |
| 素材发想 | “基于此素材生成总纲候选”读取创作方向和全书规划正式来源 | 每次最多选择 20 条已保存的候选/已采用素材；未选素材不进入上下文。当前没有独立的地点 AI 生成入口 |

## 章节与候选边界

章节关系只能使用 `drafts.blueprint_chapter_number`。Blueprint v2 的原始 Markdown、revision 和 contentHash 保持不变；任何人工确认仍由原 review/confirmation 链路完成。候选正文审批和素材记录状态是两个不同领域，互不代替。
